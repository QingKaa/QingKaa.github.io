浏览器渲染原理

清咖
2024-07-05
浏览器
tags: 浏览器渲染原理面试基础题

1. HTML解析

预解析线程： 在开始解析前，会启动一个预解析线程，预解析线程会对html文档进行快速的浏览，率先下载html中的Css文件和js文件。css解释会在这个线程进行。
主线程： 主线程开始解析html文档，在这个过程中遇到Css引入的link标签不会被阻塞，遇到script文件，则会被阻塞。因为js可能会修改html文档，所以js文件会阻塞。

script 标签：
当 <script>标签设置了 async 属性时，浏览器会异步地加载脚本文件，并且在下载完成后立即执行脚本，而不会等待页面的渲染。
如果不使用 async 且 defer="defer"：脚本将在页面完成解析时执行
如果既不使用 async 也不使用 defer：在浏览器继续解析页面之前，立即读取并执行脚本

最终这个过程会产出 DOM 树结构和 CSSOM 树。

2. 样式计算

通过上一过程，得到的 DOM 树和 CSSOM 树。通过遍历 DOM 树，为每一个 DOM 节点，计算它的所有 CSS 属性 。

计算的过程：

  1. 确定声明值；
  2. 层叠冲突；
  3. 使用继承；
  4. 使用默认值

这个阶段会产出一个带样式的 DOM 树结构

4. 布局（Layout）

根据 DOM 树里每个节点的样式，计算出每个节点的确切尺寸和位置。

有一些数值，例如：百分比，或者auto，在上一步骤无法算出来，在布局这个过程才能算出来。

Layout树和DOM树不一定是一一对应的。
布局树是记录节点的几何信息(尺寸和位置)的，如果设置了display: none;，则节点失去几何信息，不会被添加到布局树中。
伪元素节点不存在于DOM树中，但是有几何信息，因此会被生成到布局树中。

这个阶段产出 layout树

5. 分层（Layer）

主线程会使用一套复杂的策略对整个布局树中进行分层。
分层的好处在于，将来某一个层改变后，仅会对该层进行后续处理，从而提升效率。

6. 绘制（Paint）

生成绘制的指令，为每个层生成绘制指令集，用于描述这一层的内容该如何画出来(绘制指令类似于canvas的操作方法)

7. 分块（Tiling）

分块将每一层分为多个小的区域。达到优先画出视口内以及接近视口的内容的效果。

分块的工作是交给多个线程同时进行的:
渲染主线程先将分块任务交给合成线程，合成线程会从线程池中拿取多个线程来完成分块工作。
其中的合成线程和渲染主线程都位于渲染进程里。

8. 光栅化（Raster）

光栅化将每个块变成位图 。

位图：可以简单理解成用二维数组存储的像素信息。

这个操作是在GPU进程进行的。

最后GPU将产出位图，供给合成线程

9. 画（Draw）

合成线程计算出每个位图在屏幕上的位置，交给GPU进行最终呈现
