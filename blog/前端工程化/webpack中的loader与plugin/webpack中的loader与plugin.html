webpack中的loader与plugin

loader

webpack 只能理解 JavaScript 和 JSON 文件，这是 webpack 开箱可用的自带能力。loader 让 webpack 能够去处理其他类型的文件，并将它们转换为有效 模块，以供应用程序使用，以及被添加到依赖图中。

大白话：

  1. loader 是一个函数，它接受源文件作为参数，然后返回该函数处理后的结果。
  2. loader 可以是同步的，也可以是异步的。
  3. loader 运行在 Node.js 中，并且可以完全使用 Node.js 的文件系统。
  4. 多个 loader 执行顺序是从右到左，从下到上
module.exports = {
  module: {
    rules: [
        { test: /\.txt$/, use: 'raw-loader' },
        { test: /\.css$/,
            use: [
            { loader: 'style-loader' },
            {
                loader: 'css-loader',
                options: { modules: true, },
            },
            { loader: 'sass-loader' },
            ],
        }
    ],
  }
  //...
};

如何编写Loader

loader支持链式调用，上一个loader的执行结果会作为下一个loader的入参
返回值必须是标准的JavaScript字符串或者AST代码结构

Loader接收三个参数
source： 资源输入 对于第一个执行的loader为资源文件的内容 后续执行的loader则为前一个loader的执行结果 也可能是字符串 或者是代码的AST结构
sourceMap： 可选参数 代码的sourcemap结构
data： 可选参数 其他需要在Loader链中传递的信息

Loader 开发工具
loader-utilsopen in new window loader-utils 是一个非常重要的 Loader 开发辅助工具，为开发中提供了诸如读取配置、requestString的序列化和反序列化、getOptions/getCurrentRequest/parseQuery等核心接口....等等功能，对于loader的开发十分有用
schema--utilsopen in new window：schema-utils是用于校验用户传入loader的参数配置的校验工具，也是在开发中十分有用

loader是无状态的
loader 不应该保存状态

上报loader的异常信息
尽量使用logger.error 减少对用户的干扰
对于需要明确警示用户的错误 优先使用 this.emitError
对于已经严重到不能继续往下编译的错误 使用 callback

loader函数中的this
this 由webpack提供，并指向loader-runtime的loaderContext 对象
可以通过this来获取loader需要的各种信息 Loader Context提供了许多实用的接口，我们不仅可以通过这些接口获取需要的信息，还可以通过这些接口改变webpack的运行状态

一个简单的例子：

// no-console-loader.js

// 导出一个函数，这个函数接收源文件的内容 source
module.exports = function (source) {
  // 删除源文件中的所有 console.log 语句
  const strippedSource = source.replace(/console\.log\(.+?\);?/g, "");

  // 返回处理后的结果
  return strippedSource;
};

plugin

webpack 插件是一个具有 apply 方法的 JavaScript 对象。apply 方法会被 webpack compiler 调用，并且在 整个 编译生命周期都可以访问 compiler 对象

webpack插件示例：

const pluginName = 'ConsoleLogOnBuildWebpackPlugin';

class ConsoleLogOnBuildWebpackPlugin {
  apply(compiler) {
    compiler.hooks.run.tap(pluginName, (compilation) => {
      console.log('webpack 构建正在启动！');
    });
  }
}

module.exports = ConsoleLogOnBuildWebpackPlugin;

常见的plugin

compiler钩子

Compiler 模块是 webpack 的主要引擎，它通过 CLI 或者 Node API 传递的所有选项创建出一个 compilation 实例。 它扩展（extends）自 Tapable 类，用来注册和调用插件。 大多数面向用户的插件会首先在 Compiler 上注册。

compiler-hooksopen in new window

entryOption: 在设置 entry 之前调用，允许修改 webpack 配置中的 entry。

compiler.hooks.entryOption.tap("MyCustomPlugin", (context, entry) => {
      // 修改 entry
      console.log("compiler => entryOption : entry", entry);
    });

afterPlugins: 在 webpack 加载并初始化完所有插件之后调用。

compiler.hooks.afterPlugins.tap("MyCustomPlugin", (compiler) => {
      console.log("compiler => afterPlugins 已加载完所有插件");
      const plugins = compiler.options.plugins;
      plugins.forEach((plugin, index) => {
        console.log(`===: 插件 ${index + 1}:`, plugin.constructor.name);
      });
    });

run: 在开始读取 records 之前调用，表示 webpack 开始构建

compiler.hooks.run.tap("MyCustomPlugin", (compiler) => {
      console.log("compiler => run 构建过程开始");
    });

emit: 在生成资源并输出到目录之前调用。

compiler.hooks.emit.tapAsync("MyCustomPlugin", (compilation, callback) => {
      console.log("compiler => emit 即将生成文件");
      callback();
    });

done: 在 webpack 完成构建并且输出了所有资源后调用。

compiler.hooks.done.tap("MyCustomPlugin", (stats) => {
      console.log(
        "compiler => done 构建完成，耗时:",
        stats.endTime - stats.startTime,
        "ms"
      );
    });

compilation: 在创建新的 compilation 实例之后调用,在这里面可以给compilation绑定钩子。

compiler.hooks.compilation.tap(
      "MyCustomPlugin",
      (compilation, { normalModuleFactory }) => { 
        console.log("compiler => compilation ");
      }
    );

afterCompile: [AsyncSeriesHook] compilation 结束和封印之后执行。

compilation钩子

大致分为几类钩子：

模块构建（Module building）相关的钩子
这些钩子允许在 webpack 构建每个模块时执行任务，例如 buildModule、succeedModule、finishModules, seal 等。

模块优化（Optimization）相关的钩子：
这类钩子用于在 webpack 优化资源的不同阶段执行任务，例如 optimize、optimizeTree、afterOptimizeTree、optimizeModules、afterOptimizeModules 等。

资源管理（Asset management）相关的钩子：
用于管理生成的资源，例如 processAssets、afterProcessAssets 等。

模块解析（Module resolution）相关的钩子：
这些钩子允许在解析模块路径时执行任务，例如 beforeResolve、afterResolve 等。

buildModule： 在模块构建开始之前触发，可以用来修改模块。

compilation.hooks.buildModule.tap("MyCustomPlugin", (module) => {
          console.log("===: compilation => buildModule ", module.rawRequest);
        });

finishModules: [AsyncSeriesHook] 所有模块都完成构建并且没有错误时执行。

compilation.hooks.finishModules.tapAsync(
          "MyCustomPlugin",
          (modules, callable) => {
            console.log("===: compilation => finishModules");
            callable()
          }
        );

optimize： [SyncHook]优化阶段开始时触发。

compilation.hooks.optimize.tap("MyCustomPlugin", () => {
          console.log("===: compilation => optimize");
        });

afterOptimizeModules: 在模块优化阶段开始时调用。插件可以 tap 此钩子对模块进行优化。

 compilation.hooks.afterOptimizeModules.tap(
          "MyCustomPlugin",
          (modules) => {
            modules.forEach((module) => {
              console.log(
                "===: compilation => afterOptimizeModules ",
                module.rawRequest
              );
            });
          }
        );

如何编写Plugin

在compiler以及compilation的各个钩子中注册事件，通过注册的事件对文件内容进行处理。

上文提到的各个钩子完整代码：

class MyCustomPlugin {
  constructor(options) {
    this.options = options;
  }
  apply(compiler) {
    compiler.hooks.entryOption.tap("MyCustomPlugin", (context, entry) => {
      console.log("compiler => entryOption : entry", entry);
    });

    compiler.hooks.afterPlugins.tap("MyCustomPlugin", (compiler) => {
      console.log("compiler => afterPlugins 已加载完所有插件");
      const plugins = compiler.options.plugins;
      plugins.forEach((plugin, index) => {
        console.log(`===: 插件 ${index + 1}:`, plugin.constructor.name);
      });
    });

    compiler.hooks.run.tap("MyCustomPlugin", (compiler) => {
      console.log("compiler => run 构建过程开始");
    });

    compiler.hooks.emit.tapAsync("MyCustomPlugin", (compilation, callback) => {
      console.log("compiler => emit 即将生成文件");
      callback();
    });

    compiler.hooks.done.tap("MyCustomPlugin", (stats) => {
      console.log(
        "compiler => done 构建完成，耗时:",
        stats.endTime - stats.startTime,
        "ms"
      );
    });

    compiler.hooks.make.tapAsync("MyCustomPlugin", (compilation, callback) => {
      console.log("compiler => make ");
      callback();
    });

    compiler.hooks.afterCompile.tapAsync(
      "MyCustomPlugin",
      (compilation, callback) => {
        console.log("compiler => afterCompile ");
        callback();
      }
    );

    compiler.hooks.compilation.tap(
      "MyCustomPlugin",
      (compilation, { normalModuleFactory }) => {
        console.log("compiler => compilation ");

        // 构建阶段
        compilation.hooks.buildModule.tap("MyCustomPlugin", (module) => {
          console.log("===: compilation => buildModule ", module.rawRequest);
        });

        compilation.hooks.finishModules.tapAsync(
          "MyCustomPlugin",
          (modules, callable) => {
            console.log("===: compilation => finishModules");
            callable();
          }
        );

        compilation.hooks.seal.tap("MyCustomPlugin", () => {
          console.log("===: compilation => seal");
        });

        // 优化阶段
        compilation.hooks.optimizeDependencies.tap(
          "MyCustomPlugin",
          (modules) => {
            console.log("===: compilation => optimizeDependencies");
          }
        );

        compilation.hooks.optimize.tap("MyCustomPlugin", () => {
          console.log("===: compilation => optimize");
        });

        compilation.hooks.afterOptimizeModules.tap(
          "MyCustomPlugin",
          (modules) => {
            modules.forEach((module) => {
              console.log(
                "===: compilation => afterOptimizeModules ",
                module.rawRequest
              );
            });
          }
        );

        // 资源管理
        compilation.hooks.processAssets.tap("MyCustomPlugin", (assets) => {
          console.log("===: compilation => processAssets");
        });
        compilation.hooks.afterProcessAssets.tap("MyCustomPlugin", (assets) => {
          console.log("===: compilation => afterProcessAssets");
        });
        // ...
      }
    );
  }
}

module.exports = MyCustomPlugin;
